## 1. 已实现内容

| 模块 | 位置 | 说明 |
|---|---|---|
| 配置与就绪清单 | `apps/server/src/ilab/config.ts` | 默认 `ILAB_MODE=mock`、`ILAB_NETWORK_ENABLED=false`；就绪清单只报告“是否已配置/已确认” |
| 签名与编码 | `signature.ts` | MD5(UTF-8 原文)大写；ticket 从原始 URL 只解码一次（`+` 不变空格）；出站只编码一次；日志脱敏；令牌 AES-256-GCM 加密 |
| 客户端 | `client.ts`、`mockClient.ts` | 真实客户端需“模式一致 + 外连开关”双重放行；业务 code≠0 一律按失败；超时为“结果未知”；mock 平台实现签名、令牌 10 次、刷新 2 次、status=1 不可改、附件规则与故障注入 |
| 身份与入口 | `identity.ts`、`routes.ts` | `GET /ilab/launch` 立即换票 → HttpOnly 单次 handoff → 303 到不含 ticket 的地址 → `POST /api/ilab/bootstrap` 只返回本校令牌；身份键 provider/环境/appid/un，外部用户恒为 student，不与同名本地账号合并 |
| 过程采集 | `telemetry.ts`、`routes/experiment.ts` | 服务器时间记录打开/改动/暂停/恢复/关闭；每次提交追加一条 `step_attempts`（尝试序号、墙钟起止、active 时长、证据质量）；`requestId` 幂等 |
| AI 审计 | `aiAudit.ts`、`routes/ai.ts` | 每次评审写 `ai_invocations`：未配置/已收到响应/HTTP 错误/超时/网络错误、usage、解析是否成功、最终来源 |
| 导出映射 | `mapper.ts`、`validate.ts` | 24 步 → 回传 JSON；缺失即阻断，不补造；两种整数口径候选；Schema + 跨字段校验 |
| 报告文件 | `pdf.ts` | pdfkit 生成 PDF，嵌入中文字体子集；无可嵌入字体时阻断 |
| 回传队列 | `outbox.ts` | 冻结 → `data_upload(status=1)` → 同 originId 原始字节附件；超时/已存在先 `data_get` 对账；只读锁定；附件单独重试 |
| 前端 | `hud/IlabSync.tsx` 等 | 入口引导、顶栏“实验空间”标识、S24“结束实验并提交”确认与状态、阻断项列表、PDF 查看；面板打开/关闭/改动/隐藏事件 |

数据库迁移见 `apps/server/src/ilab/migrate.ts`：只新建表、追加列（`schema_version=1`），不删除、不改写已有记录。回退方法：切回旧版本代码即可（旧代码不读新表/新列）。

## 2. 本地运行与演示

```bash
pnpm install
pnpm dev
```

- 浏览器打开 http://localhost:5174 ，登录页点击“模拟从实验空间进入（仅开发 · 合成数据）”，即走完整的换票与 handoff 流程（此按钮不会出现在生产构建中）。
- 完成 24 步后，在 S24 复盘与报告终端的“实验空间同步”中点击“结束实验并提交到实验空间”。mock 环境中，待确认口径只作为提示显示，记录提交到本地模拟平台，**不会发送到实验空间**。
- 部署前在服务器上检查报告字体：`pnpm --filter @zhian/server exec tsx scripts/check-report-font.ts out.pdf`

## 3. 回传规则（与代码一致）

- **时间**：步骤开始 = 服务器观测到的首次打开设备面板；结束 = 最后一次提交；导出时起止都向下取整到秒，`timeUsed` = 两者之差（候选口径，待确认）。整体开始 = 绑定会话创建时间（换票之后）。`duration_ms` 只是判分耗时，不参与。
- **阻断项**（测试/正式环境不能提交）：历史无证据（legacy_missing）、缺开始记录、用时不足 1 秒、未来时间、步骤超出整体范围、expectTime 未确认、整数/时间/AI 口径未确认、实际交互步骤不足 20、完成记录不足 10 步、仍有未结束的模型请求、模型版本/部署未配置、报告字体缺失、合成数据或环境不一致。
- **实际交互**：步骤内服务器记录到“改动输入”事件才算；S24 自动报告、只打开不改动就提交都不算。S01–S23 共 23 个候选。
- **成绩**：原始分不改。`preserve_weights_round` 步骤与总分各自四舍五入（步骤和可能与总分差 1–2 分，会给出提示，不调分）；`normalize_step_percent` 步骤满分导出为 100。
- **AI 计数**：未配置模型 → 0；收到响应但解析失败 → 仍是一次真实调用；超时/上游错误只在 `dispatched` 口径下计数。usage 不完整时省略 token 字段；版本未知时阻断，不填 “1.0”。报告模板、仿真、评分、三维画面都不是模型调用。
- **originId**：`zhian_<环境>_<时间>_<随机>`，仅字母数字下划线，绑定会话时生成，重试不更换；需要重做时新建会话与新 originId。
- **调用预算**：每次进入默认 8 次外部调用（不含换票），不循环重试；code=18 不刷 token。

## 4. 学校部署（反向代理示例）

```nginx
location /ilab/ { proxy_pass http://127.0.0.1:8788; }
location /api/  { proxy_pass http://127.0.0.1:8788; }
location /      { root /srv/zhian/web; try_files $uri /index.html; }
# 访问日志不得记录 query：log_format 中用 $uri 而不是 $request_uri
```

正式实验链接为 `https://<学校域名>/ilab/launch`，不能使用 localhost。服务器时钟需与标准时间同步。

## 6. 仍需学校/平台提供或确认

- 官方测试页的公用测试凭据（由使用者自行填入服务器私有配置），以及测试联调的执行授权。
- 每步合理用时 expectTime（填写 `apps/server/config/step-expect-time.pending.json`）。
- 整数成绩口径、时间整秒口径、AI 计次口径（失败/超时/重试是否计次）。
- 真实模型的名称、版本、部署方式（如启用安全助手模型）。
- 正式课程权限与正式 appid/SECRET、学校 HTTPS 域名与服务器、并发与排队方案、等保二级与第三方测评材料。
- 正式接入后组织不少于 3 名真实用户、10 条真实记录的核验（合成数据不能替代）。
